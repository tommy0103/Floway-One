# API keys and Agent Setup

Read `concepts.md` first. **API Keys** are client credentials for Floway's local Gateway. They are separate from the external provider API key in an Upstream. The table shows key name, scope, creation and last-use details; select a key to see **Set Up Your Agents**. A key scoped to selected Upstreams limits client routing; **All** permits every service the owner can access. Explain scope before creating or changing it.

Use **Create API Key** for a new client identity, then inspect **Name**, generation/custom key choice, available Upstreams, and retention controls. Let the owner handle any visible secret in a masked field or secure copy flow. Do not reveal, paste, or recite it. **Rotate** invalidates the old key for its clients; **Delete** removes access. Identify dependent clients and exact key before either action, then verify the resulting key row and client behavior.

**Request dump retention** enables capture of model-invoking requests for the chosen window, which can include sensitive prompts and responses. Reducing or disabling it deletes older or all captured requests for that key. **Stateful OpenAI Responses retention** stores items needed by follow-up requests referencing an ID; reducing or disabling it can break those references. They are independent choices. Explain the effect and verify the saved setting.

**Set Up Your Agents** offers a setup script or config snippet for a selected key, agent, platform and model choice. Inspect the selected key and model first. For direct agent edits, follow `direct-setup.md`: show exact config changes with secrets masked, back up original files, use `floway agent-key` for a persistent all-service key, then validate the agent and report the backup. Never use a temporary `test-model` key as a lasting agent credential. If the owner explicitly asks to operate Agent Setup in the GUI, stay in the app and follow its current controls; do not run an install script without seeing what it will change.
